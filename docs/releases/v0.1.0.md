The first public release of **grepalert**: alerts from your logs in five minutes. No Loki, no Elasticsearch, no
database. An agent tails your log files, matches patterns and posts a clean message to Slack, Teams or any
webhook. Run it on one server, or manage a whole fleet from the dashboard.

## Highlights

### An agent that turns log lines into alerts
- **Rules in one YAML file**: a regex pattern, an optional `exclude`, severity and labels, for any file or
  `*.log` glob. Rotation and truncation are followed, and read positions are saved, so a restart neither
  misses nor repeats lines.
- **Your message, not the raw line**: name parts of the line in the pattern (`(?P<datasource>\S+)`) and use
  them in the webhook template. `Datasource DS1 is suspended because pool exhausted` becomes
  **"Critical, DS1 is suspended"**.
- **No alert storms**: suppression per rule, and per captured value. For example, one alert per datasource
  per 10 minutes, then a single "N more were held back" summary.
- **Absence rules**: alert when an expected line (a heartbeat, a nightly job) stops appearing, and again
  when it's back.
- **Change rules without a restart**: save `rules.yaml` and the agent applies it within 10 seconds. A
  broken file is rejected and the last good rules keep running. `grepalert-agent -check` validates a file
  first.
- **Memory that stays flat**: everything the agent keeps is bounded, with a 64 MiB soft limit by default.
  Tested on multi-GB files and many files per agent.

### A dashboard for a fleet
- **Groups share one rule set**, edited in the UI or synced from GitHub, GitLab or a URL. Agents enroll
  with a token and join groups by label. They connect out, so servers need no inbound port.
- **One alert instead of fifty**: the same alert from many hosts is combined ("on 12 hosts"). Silences,
  alert history, and agent-down and agent-back alerts are included.
- **Safe rule changes**:
  - every version is kept, with diffs and one-click rollback
  - **staged rollout** (one agent, then 10%, then all) that stops by itself when the new version's agents
    alert far more than the others
  - a **dry run** that replays the last hours of real logs through draft rules
- **Rule playground**: paste log lines and see what matched, what was captured, and the exact body each
  webhook would receive.
- **Local rules**: extra rules for one machine, on top of its group's.
- **Keeps working when the dashboard is down**: agents alert the webhook directly after 15 seconds, and
  their rules, read positions and silences survive a restart.
- **Sign-in with SSO** (OpenID Connect: Okta, Entra ID, Keycloak and others) and/or local accounts.
  Viewer, editor and admin roles per group, and an audit log with diffs of every change.

### Easy to run
- **Two static binaries**, for Linux, macOS and Windows. The dashboard's web UI is embedded in its
  binary.
- **Container images** for linux/amd64 and linux/arm64. They run with a few environment variables, no
  config file needed.

## Get started

**One server, no dashboard.** Write a `rules.yaml` and run the agent:

```bash
docker run -d --name grepalert-agent \
  -e SLACK_WEBHOOK_URL=https://hooks.slack.com/... \
  -v $PWD/grepalert:/var/lib/grepalert -v /var/log:/var/log:ro \
  ghcr.io/fadhaw/grepalert-agent:0.1.0
```

**The full demo**: three agents, the dashboard, rules from a stand-in git repository and staged rollout:

```bash
git clone https://github.com/fadhaw/grepalert.git
cd grepalert/examples/compose
docker compose up -d --build
```

Open http://localhost:9400 and sign in as `admin` / `demo`; alerts arrive at http://localhost:9599. The
[README](https://github.com/fadhaw/grepalert#readme) covers installing the binaries, the dashboard
container and single sign-on.
