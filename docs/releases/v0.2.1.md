**No lost lines around log rotation.** This release fixes two rotation cases where the agent could
miss lines, and stops it from holding on to deleted log files. No changes are needed to rules or
configs.

## Fixes

- **Lines written to the old file after a rotation are alerted on.** With rename rotation (logrotate's
  default), some programs keep writing to the renamed file until they reopen their log: nginx until it
  gets `USR1`, or programs with buffered writes. The agent used to stop reading the old file as soon as
  the new one appeared, so those last lines were lost. It now keeps reading the old file for 30 seconds.
- **copytruncate followed by a burst no longer skips lines.** If a file was emptied and then written past
  its old size before the agent's next check, the agent didn't notice the truncation. It resumed in the
  middle of the new content, and the first lines after the rotation were lost. The agent now compares
  the start of the file with what it read, not only the size.
- **A line cut in two by a rotation is kept whole.** The unfinished last line of a rotated file used to
  be dropped. It now stays with the old file, and is never joined to the first line of the new one.
- **Deleted log files no longer keep their disk space.** A file whose name disappeared and was never
  recreated stayed open for good, so the disk space it used was never freed. The agent now closes it
  after 30 seconds, and reads the file from the start if it comes back.

- **Built with Go 1.27.3**, which fixes a vulnerability in the Go standard library's certificate
  verification ([GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809), `crypto/x509`), reachable from the
  dashboard.

Measured in Docker on Linux, five rotations each, against v0.2.0:

| Scenario | v0.2.0 | v0.2.1 |
|---|---|---|
| Rename rotation, program writing to the old file for 2 s after each rotation | 570 of 650 lines | **650 of 650** |
| copytruncate, then right away a burst larger than the old file | 40 of 135 lines | **135 of 135** |
| Log file deleted | held open for good | closed after 30 s |

## Documentation

- **Tested behaviour:** a new page lists what is tested, especially in edge cases: log rotation,
  restarts, Kubernetes streams, the dashboard going down, staged rollout. Each item names the test that
  checks it. See [Tested behaviour](https://github.com/fadhaw/grepalert/blob/main/docs/testing.md).
- **Files are held open, read-only:** why the agent keeps log files open, and what that means for
  writing, renaming, truncating and deleting them on Linux, macOS and Windows. See
  [Running agents](https://github.com/fadhaw/grepalert/blob/main/docs/agents.md#files-are-held-open-read-only).
- **logrotate advice:** prefer rename + create over `copytruncate`, with an example config. With
  `copytruncate`, a line written between logrotate's copy and its truncate is in neither file.
- **Documentation site:** lists and code blocks inside numbered steps now display correctly; on the
  Install page, the commands inside the steps showed as plain text.

## Upgrading

Replace the binary or image; nothing else changes. After each rotation the agent now keeps the old
file open for 30 seconds longer, so it may briefly hold one more open file per rotated log.
