**Kubernetes**: grepalert can now alert on the logs of the pods a label selector picks, without
a log pipeline, a sidecar or a DaemonSet. One small agent in the cluster follows them through the
Kubernetes API. No changes are needed to existing rules or configs.

## Alerts from pod logs

- **A `kubernetes:` source instead of `files:`.** A rule names a namespace (or `"*"`), a label
  selector and, optionally, a container:

  ```yaml
  - name: checkout-errors
    kubernetes: {namespace: shop, selector: app=checkout, container: app}
    pattern: 'ERROR (?P<code>\w+)'
    webhooks: [chat]
  ```

  Captures, templates, suppression, absence rules, groups and staged rollout all work as for files.
  Alerts say where the line came from: `k8s:shop/checkout-7d9f8-x2lkq/app`.
- **Follows the pods as they change.** Every 10 seconds the agent re-checks the selector:
  - new replicas are picked up and read from their first line
  - pods that are gone are dropped
  - restarted containers are followed again from where they stopped
- **Nothing lost, nothing repeated.** A dropped stream resumes after the last line it handled, and
  the position is saved, so a restarted agent resumes too.
- **Read-only and small.** The agent needs only `get`/`list` on pods and `get` on `pods/log`, and
  reads the cluster with its pod's service account. From outside, it uses a kubeconfig (token or
  client certificate). It talks to the API directly, so the binary stays small.
- **Ready to apply:** [examples/kubernetes](https://github.com/fadhaw/grepalert/tree/main/examples/kubernetes)
  holds the agent (RBAC, rules in a ConfigMap, a hardened non-root Deployment) and a demo app. Edit
  the ConfigMap, and the running agent applies the new rules within a minute. See the
  [Kubernetes guide](https://github.com/fadhaw/grepalert/blob/main/docs/kubernetes.md).

## Log files on Kubernetes volumes

- **The generic way works on Kubernetes too:** an app writes log files to a persistent volume, and
  the agent mounts it read-only and tails it with ordinary `files:` rules, including rotation and
  saved positions. [files-on-pv.yaml](https://github.com/fadhaw/grepalert/blob/main/examples/kubernetes/files-on-pv.yaml)
  is a complete example, and the guide also shows the sidecar variant.

## Documentation

- **A documentation site:** [fadhaw.github.io/grepalert](https://fadhaw.github.io/grepalert/),
  with search, built from the same Markdown as the repository.
- **One path from install to fleet:** the README and the guides were rewritten to read in order,
  and each config file has a complete reference: every setting, its default, and a full example
  that is tested against the real parsers.
- **Rule cookbook:** twelve complete recipes for harder cases, such as slow 5xx responses, numeric
  thresholds, JSON logs, Java exceptions, SSH brute force, per-tenant alerts, and Opsgenie and
  Slack Block Kit payloads. Each one is tested: its sample lines must produce exactly the webhook
  bodies shown. See the [Rule cookbook](https://github.com/fadhaw/grepalert/blob/main/docs/cookbook.md).
- **Quick-start files in the archives:** the release archives now include the quick-start configs,
  so you can start an agent right after unpacking.

## Fixes

- An invalid rules file is reported once, instead of on every check (every 10 seconds) until it
  is fixed. The last good rules keep running, as before.
