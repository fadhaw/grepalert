**See what the agent is doing.** The agent's own log now tells you which files it reads, why a
pattern finds nothing, which lines matched a rule, and whether each alert reached its webhook. Turn on
`log_level: debug` to follow a rule from the log line to the webhook, without opening the dashboard.

## Which files the agent follows

- **Logged at start, and whenever the rules change:** each file the agent follows, the rules that read
  it, and where it starts reading (the end, a saved position, or the beginning):

  ```
  level=INFO msg="following file" file=/var/log/app/app.log rules=app-errors from=end
  ```

- **A pattern that matches nothing says why.** Before, an agent that wasn't allowed to list a log
  directory followed no files and reported nothing. Now it logs a warning with the reason, and the
  dashboard shows it as an error event:

  ```
  level=WARN msg="no files match" pattern=/data/*/logs/*.log reason="cannot list /data/shop: permission denied"
  ```

  When there is simply nothing there yet, that is an `INFO` line instead. Each message is logged once,
  not on every rescan.
- **Files that don't exist yet** are logged once while the agent waits for them, and again when they
  appear.

## Debug logging: `log_level`

- **A new `log_level` setting** in agent.yaml: `debug`, `info` (the default), `warn` or `error`. Also
  `grepalert-agent -debug`, and `GREPALERT_LOG_LEVEL` for the container image.
- **At `debug`, every line a rule matches is logged** with the rule, the file, the line, the captured
  values, and what happened to it: sent as an alert, suppressed, or excluded.

  ```
  level=DEBUG msg="rule matched, sending alert" rule=deploy-failed file=app.log line="ERROR Failed to deploy \"billing\"" groups=map[app:billing]
  level=DEBUG msg="rule matched, alert suppressed" rule=deploy-failed file=app.log line="..." groups=map[app:billing] suppressed_in_window=1
  ```

- **No cost when it's off:** lines that don't match still cost no allocations, and below `debug` the
  agent doesn't build any of these messages.

## Webhook deliveries in the log

- **Failed deliveries are logged at every level** (`WARN`), after the last retry, with the error and
  the number of attempts. Before, they only appeared in the dashboard's Events tab.
- **Successful deliveries are logged at `debug`,** with the HTTP status, attempts and time taken:

  ```
  level=DEBUG msg="webhook delivered" rule=deploy-failed webhook=chat status=200 attempts=1 took=5ms
  level=WARN msg="webhook delivery failed" rule=deploy-failed webhook=pager attempts=3 took=3.01s err="HTTP 502: upstream down"
  ```

- **A full webhook queue** is logged as a warning, at most every 10 seconds, with the number of alerts
  dropped so far.
- **Agents connected to a dashboard** log, at `debug`, that they handed an alert to the dashboard (which
  sends it), or sent it themselves while the dashboard was unreachable.

See [Debugging rules](https://github.com/fadhaw/grepalert/blob/main/docs/rules.md#debugging-rules) and
[Which files an agent follows](https://github.com/fadhaw/grepalert/blob/main/docs/agents.md#which-files-an-agent-follows).

## Upgrading

Replace the binary or image; existing configs work unchanged, and `log_level` defaults to `info`. The
agent's log has a few more lines than before: one per followed file at start, and a warning for each
failed webhook delivery. `debug` writes a line for every match, so turn it off again on busy logs.
